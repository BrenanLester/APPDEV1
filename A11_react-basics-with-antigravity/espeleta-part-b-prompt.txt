## Technical Safety Requirements (to prevent rendering bugs)
These rules exist because loose theming setups commonly render text invisible or animations dead on arrival. Follow them exactly:

1. **Every CSS custom property must actually resolve.** If you introduce design tokens (`--text-primary`, `--bg-card`, `--gradient-text`, `--neon-purple`, `--radius-lg`, `--transition-normal`, etc.), define them all in one central place (e.g. a `:root` block or a single theme/tokens CSS file) and make sure that file is imported everywhere it's used. Additionally, give every `var()` usage a sensible fallback value — e.g. `color: var(--text-primary, #f5f3ff)` — so nothing goes invisible if a token is ever missing or fails to load.
2. **Never rely on `color: transparent` + `background-clip: text` without a guaranteed fallback background.** If a gradient text effect is used for a heading, the `background` property must always resolve to a real gradient (with a fallback value), or the heading will render as blank/invisible.
3. **Every referenced animation must have a matching `@keyframes` block.** If you write `animation: fadeInUp .8s ease both`, `fadeInUp` must be defined somewhere in the stylesheet you're shipping. Don't reference animation names that don't exist.
4. **Match new CSS selectors to the real JSX/DOM structure.** Before adding rules like `.card > div::before` for decorative elements (e.g. a watermark number), confirm the component actually renders that wrapper element. If it doesn't, either adjust the selector to match the real markup or add the wrapper element in the component (presentation-only, per the rules above) — don't ship a rule that silently never fires.
5. **Explicitly set text alignment for hero/header content.** A full-width container with `align-items: center` on its parent flexbox does not center inline text inside it — add `text-align: center` (or the appropriate alignment) directly where needed, and verify it visually.
